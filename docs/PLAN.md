# 抖音小游戏 · 开发与变现方案

> 项目：`DouyinGame`　开发仓库：`github.com/KZheng0106/DouyinGame`
> 当前阶段：**MVP 原型已可玩**（跳跃玩法 + 激励视频复活位，见 `docs/TECH-STACK.md` 的选型理由）

---

## 一、核心结论（先看这段）

1. **首版只做广告变现，不做内购。** 内购需要企业主体 + 版号，个人开发者这条路走不通；广告变现（激励视频为主）个人主体就能跑通全流程。
2. **先验证「好不好玩」，再谈赚钱。** 玩法不成立的项目，投多少量都是沉没成本。
3. **抖音的分发逻辑是「短平快」**：用户从视频滑进来，**首屏 3 秒内必须能操作**，单局 30~90 秒，失败点要天然产生「看广告复活」的欲望。

---

## 二、钱从哪来：四条变现路径

| 方式 | 门槛 | 收入特征 | 首版是否做 |
|---|---|---|---|
| **激励视频**（看广告复活 / 双倍奖励） | 开通流量主 | 主力收入，eCPM 显著高于其他形式 | ✅ 必做 |
| 插屏 / Banner | 同上 | 单价低，用于填充局间 | ✅ 简单加 |
| 虚拟支付（道具内购） | 企业主体 + 版号 | 单用户价值高，门槛最高 | ❌ 不做 |
| 达人分发 / 直播挂载 | 游戏有一定数据 | 放大器，不是起点 | 第二阶段 |

> 具体 eCPM 与分成比例随品类、人群、季节波动很大，**一律以「小游戏后台 → 流量主」的实际数据为准**，本文不给死数字。

**关键设计原则**

- 激励视频**必须由用户主动点击**触发，绝不能自动弹、也不能「不点广告就不让继续」；
- 广告拉取失败/用户中途关闭时，**游戏必须能正常继续**（本项目已做降级：只有 `completed` 才发奖励）；
- 单局复活次数要有上限（本项目 `MAX_REVIVES = 2`），否则用户会反感，反而掉留存。

---

## 三、品类选择标准

选品只要满足三条，缺一不可：

1. **单局 30~90 秒**，碎片时间可玩；
2. **失败点天然产生复活欲望**——这是激励视频的播放位；
3. **一局结束能立刻再来一局**，且是「我再来一次就过了」而不是「算了」。

| 品类 | 复活动机 | 开发成本 | 备注 |
|---|---|---|---|
| 跳跃 / 跑酷 | 强 | 低 | 本项目选型 |
| 合成 / 合并 | 中 | 低 | 抖音验证过的爆款赛道 |
| 消除 | 中 | 中 | 关卡设计成本高 |
| 答题闯关 | 弱 | 低 | 靠广告次数而非复活 |
| 放置挂机 | 弱 | 低 | 靠时长，不靠复活 |
| 模拟经营 | 中 | 高 | 首版不建议 |

**不建议首版做**：实时对战、重度 RPG —— 需要服务端、匹配、防作弊、反外挂，成本翻十倍，且没有版号做不了商业化。

## 四、分阶段执行计划

### Phase 0｜账号与资质（1~3 天，与开发并行）

- 在 [开发者平台](https://developer.open-douyin.com/console/apply/game) 创建小游戏，拿到 **AppID**；
- 完成开发者实名认证，确认主体类型（个人 / 企业）；
- 了解该品类需要的资质（软著等）。**这是唯一会卡住上线的事，越早办越好。**

✅ 完成标准：控制台能看到 AppID，「上传代码」入口可用。

### Phase 1｜玩法原型（3~5 天）— ✅ 已完成

- 核心循环：按住蓄力 → 松开跳跃 → 落点判定 → 计分；
- 失败点：落空坠落 → 结束 → 看广告复活；
- 试玩验证：**会不会主动再来一局**。

✅ 完成标准：单局 30~90 秒，试玩者平均连玩 ≥ 3 局。

### Phase 2｜工程搭建（2~3 天）— ✅ 已完成

- 三层架构：`core`（纯逻辑，可单测）/ `render`（Canvas 绘制）/ `platform`（tt 与浏览器双适配）；
- 构建：esbuild 单文件 IIFE → `games/jump/dist/douyin/`；
- 逻辑测试：11 项覆盖蓄力、落点、计分、复活、关卡可达性、随机可复现。

✅ 完成标准：`npm run check` 通过，`npm run build` 产出可在开发者工具中启动。

### Phase 3｜核心玩法打磨（1~2 周）

- [ ] 美术接入（替换纯色块）：角色、平台、背景、按钮
- [ ] 音效：跳跃、落地、完美、失败
- [ ] 难度曲线调优（当前已按分数收敛平台宽度与间距）
- [ ] 分数动效、连击反馈
- [ ] 首屏「一键开始」，去掉标题页停留

✅ 完成标准：点击到第一局可操作 < 3 秒，全程无明显掉帧。

### Phase 4｜商业化接入（2~3 天）

- [x] 激励视频复活（已实现，`games/jump/src/ads.ts`）
- [ ] 在流量主后台创建广告位，填入 `games/jump/src/config.ts` 的 `rewardedAdUnitId`
- [ ] **`debugFakeAd` 改为 `false`**（上线红线，否则用户不看广告也能复活）
- [ ] 插屏：局间展示，注意平台频率限制，首局不弹
- [ ] 真机验证：广告加载失败 / 中途关闭 / 完整观看，三种分支都正确

✅ 完成标准：三种广告结果下游戏状态都正确，且不影响正常游玩。

### Phase 5｜提审上线（3~7 天，含被打回重提）

见 [`docs/LAUNCH.md`](./LAUNCH.md)。

### Phase 6｜数据与获量（持续）

必须埋的指标：`DAU`、`次留 / 7 留`、`单局时长`、`人均广告观看次数`、`ARPDAU`、`eCPM`。

- 自然流量：分享卡片、短视频挂载、达人合作；
- 付费买量：**留存数据达标再开**，否则就是烧钱。
- 参考达标线：**次留 ≥ 30%，人均日看广告 ≥ 3 次**，再谈放大。

### Phase 7｜变现调优（持续）

- 调广告位置与频次（复活 / 双倍奖励 / 局间插屏）；
- 调难度曲线，提高「差一点就过」的复活率；
- A/B 测试封面、标题、分享文案。

---

## 五、审核最容易踩的三个坑

1. **诱导分享 / 诱导关注**——「分享得奖励」是明确违规。分享必须自愿。
2. **防沉迷与实名**——必须接入平台的实名/防沉迷能力，未成年人限制要生效。
3. **广告合规**——不能诱导点击、不能遮挡关闭按钮、首屏不能直接弹插屏；同时要有隐私政策。

## 六、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 玩法不出彩 | 留存崩，广告收入归零 | Phase 1 就用低成本原型验证，别急着堆美术 |
| 资质卡住上线 | 无法上线 | Phase 0 提前办软著 |
| 包体超限 | 审核不过 | 当前 12KB，远低于限制；接美术后用图集/分包 |
| 广告拒审 | 无法变现 | 严格遵守广告位规范，别做诱导 |
| 买量亏钱 | 现金流断裂 | 留存达标前不买量 |
